Descripción

Una tienda que vende en seis canales y se administraba en planillas sueltas

El contexto

Casa Tintin vende productos de hogar, bebé, oficina, auto y belleza por su web, WhatsApp, Instagram, Marketplace, Mercado Libre y venta directa. Trabaja con stock propio y con productos por encargo que despacha un proveedor, con entrega en pocos días hábiles.

Es una operación pequeña: la misma persona compra, fotografía, publica, vende y coordina los despachos.

El problema

El stock, los precios y las ventas vivían en lugares distintos. Calcular el precio con IVA y margen era manual, el catálogo de clientes había que regenerarlo y subirlo a Netlify en cada cambio, y la tienda WooCommerce mostraba precios y stock desactualizados.

No había forma de saber qué reponer, qué producto llevaba semanas sin venderse, qué publicación atraía visitas ni qué preguntaban los clientes en cada canal.

La solución es una aplicación web de administración, protegida con inicio de sesión, que funciona como la única fuente de verdad de la tienda. Cada cambio se guarda en Supabase, aparece al instante en otros dispositivos, actualiza el catálogo público en 2,5 segundos y puede enviarse a la tienda WooCommerce con un clic. Los pedidos que entran por la web vuelven a la app como ventas y descuentan stock solos.

Se construyó de forma iterativa: cada mejora se probó primero en un prototipo con datos de la tienda y recién después se desplegó. La última etapa apuntó a automatizar: que la app haga sola lo que antes requería revisar y copiar a mano.

Arquitectura

Supabase al centro, tres sitios alrededor

El navegador habla directo con Supabase usando una clave pública. La seguridad la ponen las políticas de la base de datos; las claves secretas de WooCommerce y del correo solo existen dentro de las Edge Functions.

  1. GuardarLa administradora edita un producto. Se guarda como documento jsonb y Realtime lo replica en sus otros dispositivos.
  2. Publicar2,5 s después del último cambio, la app arma el catálogo sin costos ni datos internos y lo escribe en catalog_public.
  3. SincronizarCon un clic, woo-sync empuja precios, stock y fotos a WooCommerce y trae los pedidos nuevos como ventas.

Capa de datos con cola por registro

Toda la app guarda a través de un objeto Store. Si el usuario guarda dos veces seguidas, la segunda escritura espera a la primera.

  • Un mismo código para modo local y modo Supabase
  • Cada guardado agenda la publicación del catálogo
JavaScript
// Cola por registro: dos guardados del mismo producto nunca se pisan
const chains = {};
function queued(key, fn){
  const prev = chains[key] || Promise.resolve();
  const next = prev.catch(() => {}).then(fn);
  chains[key] = next;
  return next;
}

// Cada tabla guarda el documento completo en una columna jsonb
async function supaPut(table, id, data){
  const { error } = await sb.from(table)
    .upsert({ id, data, updated_at: new Date().toISOString() });
  if (error) throw error;
}

const Store = {
  async saveProduct(p){
    if (mode === 'supa') {
      const { id, ...data } = p;

    }

    localPut(products, p); lsPersist(); render();
  },
  // saveSale, saveCoupon, saveSettings, uploadImage… siguen el mismo patrón
};
subscribeSupa() · publishCatalog() · línea 1132

Tiempo real y catálogo en vivo

Un canal escucha los cambios de la base y actualiza la lista local. La publicación del catálogo espera 2,5 s sin cambios para no escribir en cada tecla.

  • No refresca si hay un producto abierto en edición
  • Indicador "Catálogo en vivo · hora"
JavaScript
// Cambios hechos en otro dispositivo aparecen sin recargar
function subscribeSupa(){
  supaChan = sb.channel('cambios-tienda')
    .on('postgres_changes', { event: '*', schema: 'public' }, pl => {
      const t = pl.table;
      const row = pl.new && pl.new.id ? pl.new : null;
      if (t === 'config' && row?.id === 'settings') {
        settings = { ...clone(DEFAULT_SETTINGS), ...clone(row.data) };
      } else if (['products', 'sales', 'coupons'].includes(t)) {
        const list = t === 'products' ? products : t === 'sales' ? sales : coupons;
        if (pl.eventType === 'DELETE') {
          const i = list.findIndex(x => x.id === pl.old.id);
          if (i > -1) list.splice(i, 1);
        } else if (row) localPut(list, { ...row.data, id: row.id });
      } else return;
      // agrupa ráfagas y no interrumpe si hay un producto en edición
      clearTimeout(rtT);
      rtT = setTimeout(() => { if (!$('#dlgProduct').open) render(); }, 400);
    }).subscribe();
}

// Publicación del catálogo con debounce de 2,5 s
function schedulePublish(){
  clearTimeout(pubT); setPubStatus('pending');

}

}

Precio sugerido con IVA y margen

Acepta costos con o sin IVA y devuelve todo lo que la ficha necesita mostrar: costo bruto, precio sugerido, precio bruto, ganancia y margen real.

// Precio sugerido = costo con IVA × (1 + margen), redondeado
function calc(p){
  const tax = Number(p.taxRate ?? settings.taxRate) || 0;          // 19 %
  let costNet, taxAmt, costGross;
  if (p.costInclTax && Number(p.costGrossIn) > 0) {                 // costo ya trae IVA
    costGross = roundMoney(Number(p.costGrossIn));
    costNet   = roundMoney(costGross / (1 + tax / 100));
    taxAmt    = roundMoney(costGross - costNet);
  } else {                                                          // costo neto
    costNet   = Number(p.costNet) || 0;
    taxAmt    = roundMoney(costNet * tax / 100);
    costGross = roundMoney(costNet + taxAmt);
  }
  const margin = Number(p.margin ?? settings.defaultMargin) || 0;   // 60 %
  const r = Number(settings.rounding) || 1;
  const raw = costGross * (1 + margin / 100);
  const suggested = r > 1 ? Math.round(raw / r) * r : roundMoney(raw);
  const sale   = p.priceManual ? (Number(p.salePrice) || 0) : suggested;
  const profit = roundMoney(sale - costGross);
  const net    = Math.round(sale / (1 + tax / 100));               // precio bruto
  return { tax, taxAmt, costNet, costGross, suggested, sale, net, profit,
           realMargin: costGross > 0 ? profit / costGross * 100 : 0 };
}
stockPlan() · línea 2660

Stock por diferencia

En vez de sumar y restar en cada acción, compara cuántas unidades consumía la venta antes y después del cambio y aplica solo la diferencia.

  • Un solo algoritmo para crear, editar y anular
  • Valida antes de escribir: todo o nada
  • Deja registro en el historial del producto
JavaScript
// Compara la venta antes y después de editarla y mueve solo la diferencia.
// Sirve igual para crear, editar, anular o borrar una venta.
function consumption(v){
  const m = {};
  if (!v || v.status === 'cancelada') return m;
  for (const i of v.items || []) {
    const k = i.productId + '|' + (i.variantId || '');
    m[k] = (m[k] || 0) + (Number(i.qty) || 0);
  }
  return m;
}

function stockPlan(oldV, newV){
  const a = consumption(oldV), b = consumption(newV), byP = {};
  for (const k of new Set([...Object.keys(a), ...Object.keys(b)])) {
    const delta = (a[k] || 0) - (b[k] || 0);
    if (!delta) continue;
    const [pid, vid] = k.split('|');
    (byP[pid] = byP[pid] || []).push({ vid, delta, prev: a[k] || 0 });
  }
  const plan = [];
  for (const pid in byP) {
    const p = products.find(x => x.id === pid); if (!p) continue;
    const upd = clone(p); let total = 0;
    for (const { vid, delta, prev } of byP[pid]) {
      const target = vid ? upd.variants.find(x => x.id === vid) : upd;
      const nq = (Number(target.qty) || 0) + delta;
      if (nq < 0 && !p.onDemand)    // los productos por encargo no bloquean
        return { error: `No hay stock suficiente de "${p.name}". Disponible: ${target.qty + prev}.` };
      target.qty = nq; total += delta;
    }
    if (hasVariants(upd)) upd.qty = sumVariants(upd);
    plan.push({ upd, delta: total });
  }
  return { plan };                  // se aplica todo o nada
}

wooCall() · importWebOrders() · línea 3442

Pedidos de WooCommerce como ventas

La app llama a la Edge Function woo-sync, que guarda las claves de la API como secretos. Los pedidos nuevos se convierten en ventas y los cancelados devuelven stock.

  • Solo avanza estados, nunca retrocede
  • Relee una hora hacia atrás para no perder pedidos
JavaScript
// La app nunca ve las claves de WooCommerce: llama a una Edge Function
async function wooCall(action, payload = {}){
  const { data, error } = await sb.functions.invoke('woo-sync', { body: { action, ...payload } });
  if (error) throw new Error(error.message);
  if (data && data.error) throw new Error(data.error);
  return data;
}

// Pedidos de casatintin.cl → ventas de la app (con descuento de stock)
async function importWebOrders(){
  // se relee 1 hora hacia atrás para no perder pedidos en el borde
  const from = new Date(new Date(settings.wooOrders.last).getTime() - 36e5).toISOString();
  const res = await wooCall('orders', { modifiedAfter: from });
  let added = 0, updated = 0;
  for (const o of res.orders || []) {
    const ex = sales.find(v => String(v.wcOrderId || '') === o.id);
    const st = WOO_ST[o.status];                      // processing → pagada, etc.
    if (ex) {
      // solo avanza el estado; si se cancela, devuelve el stock
      if (st && st !== ex.status && (st === 'cancelada' || ST_RANK[st] > ST_RANK[ex.status])) {
        const nv = { ...clone(ex), status: st, updatedAt: new Date().toISOString() };
        await Store.saveSale(nv);
        if (st === 'cancelada') await applyPlan(stockPlanClamp(ex, nv), ex.number);
        updated++;
      }
      continue;
    }
    if (await importOrder(o, false)) added++;        // crea V-0042 y descuenta stock
  }
  return { added, updated };
}

Desafíos técnicos

Problemas reales y cómo se resolvieron

Las categorías de WooCommerce llegaban como "Work &amp;amp; Office" y no coincidían con las de la app.

Una función decEnt() decodifica entidades HTML en bucle hasta que el texto deja de cambiar, y catSuggest() empareja por puntaje aproximado.

WooCommerce descarga cada foto desde una URL y cortaba los lotes grandes por tiempo.

Se envían primero los datos simples y después las fotos en lotes de dos, con reintento y un panel que lista qué producto y qué campo falló.

Editar o anular una venta dejaba el stock descuadrado.

stockPlan() calcula la diferencia entre la venta original y la nueva, valida todo antes de escribir y registra cada movimiento.

Cambios desde el celular y el computador al mismo tiempo podían pisarse.

Cola de escritura por registro y Realtime con espera de 400 ms que no refresca mientras hay una ficha abierta.

La clave de Supabase queda visible en el navegador.

Es la clave publicable; el acceso lo controlan políticas RLS con is_admin(). Las claves de WooCommerce y Resend viven solo como secretos de Edge Functions.

Los pedidos de productos por encargo había que traspasarlos a mano al proveedor, campo por campo.

Un panel lista las ventas pendientes de pedir, con cada dato del cliente y del producto listo para copiar, y se marca la venta cuando el pedido está hecho.

Cada cambio había que enviarlo a la web con un clic, y era fácil olvidarlo.

Envío automático al guardar con una cola que agrupa cambios, sincronización periódica y un bloqueo que impide dos sincronizaciones al mismo tiempo.

El modelo del producto cambió en cada fase y había datos antiguos.

Documentos jsonb con valores por defecto al leer, y migraciones en el cliente con bandera (mig1012) que se ejecutan una sola vez.
