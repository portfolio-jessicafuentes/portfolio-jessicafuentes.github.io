Casa Tintín — Diseño e implementación de una base de datos relacional

Cómo transformé el control manual de inventario y ventas de una pyme de venta online multicanal en un modelo de datos centralizado, con indicadores de gestión automatizados.

MySQL Modelado ER SQL Normalización Aprendizaje + Servicio

1Resumen del proyecto

Casa Tintín es una pyme de venta online de artículos para el hogar, electrónicos y misceláneos, que comercializa simultáneamente por sitio web, redes sociales, WhatsApp y marketplace. Antes de este proyecto, gestionaba su inventario y ventas en una planilla Excel que se desincronizaba constantemente entre canales, generando sobreventas y sin ningún indicador de gestión sobre qué se vendía más.

Diseñé, normalicé e implementé una base de datos relacional de 8 entidades que centraliza productos, clientes, ventas y movimientos de inventario en una única fuente de verdad — y que responde directamente a las tres preguntas de negocio que la empresa no podía contestar: qué se vende más, qué está por agotarse, y qué canal genera más ingresos.

2El desafío

Vender en cuatro canales a la vez sonaba como una ventaja, pero se convirtió en el problema: cada plataforma administraba su propio "stock" de forma independiente, y nada los conectaba entre sí.

  • Sobreventas: un producto se vendía por WhatsApp cuando ya no había stock, porque se había vendido antes por el marketplace.
  • Cero visibilidad: no existía forma de saber qué producto era el más rentable o qué canal generaba más ingresos.
  • Datos frágiles: toda la operación dependía de que una persona actualizara manualmente una planilla después de cada venta.

5Código destacado

Extracto del script de creación de la base (DDL) — cada venta descuenta stock desde una única fuente, sin importar el canal de origen:

DDL — casa_tintin_base_datos.sql
CREATE TABLE producto (
    id_producto   INT AUTO_INCREMENT PRIMARY KEY,
    id_categoria  INT NOT NULL,
    id_proveedor  INT,
    nombre        VARCHAR(100) NOT NULL,
    precio        DECIMAL(10,2) NOT NULL,
    stock_actual  INT NOT NULL DEFAULT 0,
    stock_minimo  INT NOT NULL DEFAULT 0,
    CONSTRAINT fk_producto_categoria FOREIGN KEY (id_categoria) REFERENCES categoria(id_categoria),
    CONSTRAINT fk_producto_proveedor FOREIGN KEY (id_proveedor) REFERENCES proveedor(id_proveedor)
);

CREATE TABLE movimiento_inventario (
    id_movimiento INT AUTO_INCREMENT PRIMARY KEY,
    id_producto   INT NOT NULL,
    id_venta      INT,
    tipo          ENUM('entrada','salida') NOT NULL,
    cantidad      INT NOT NULL,
    fecha         DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    motivo        VARCHAR(150),
    CONSTRAINT fk_movimiento_producto FOREIGN KEY (id_producto) REFERENCES producto(id_producto),
    CONSTRAINT fk_movimiento_venta FOREIGN KEY (id_venta) REFERENCES venta(id_venta)
);

Consulta de indicador de gestión — productos más vendidos por unidades:

SQL — indicador de gestión
-- Productos más vendidos (unidades)
SELECT p.nombre,
       SUM(dv.cantidad) AS unidades_vendidas
FROM detalle_venta dv
JOIN producto p ON p.id_producto = dv.id_producto
GROUP BY p.id_producto, p.nombre
ORDER BY unidades_vendidas DESC;
